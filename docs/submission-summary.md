KEPT builds a graph of every promise a product makes about itself. Each claim is read from the prose that states it and cited to a file and line, its text copied verbatim from disk at build time, so a promise whose citation does not resolve never enters the graph. Each promise is bound to a Kane CLI test, and the binding is kept honest from both directions: a code change re-verifies the promises in its blast radius, and a documentation change reconciles what the suite now owes. When a promise goes red, Kane's verdict selects one of three repairs: patch the code, evolve the test, or amend the documentation. The third branch is what most tooling cannot do.
